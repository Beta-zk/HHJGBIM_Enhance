# 2026-08-28 工作日志

## 修复：原材料仓页面宿主容器宽度锁定导致缩放留白

- **根因定位**：脚本中唯一改写宿主元素宽度的代码是 `material-inventory` 模块的 `injectStyleFix()`（`src/modules/material-inventory/index.ts`）。它只写入 `maxWidth: 100%`，未写入 `width`。宿主元素 `#app .app-wrapper .app-main .container.abs100` 若存在固定 `width`（如 1600px），放大窗口时宽度仍锁定，右侧留白。
- **修复内容**：`injectStyleFix()` 改为同时写入 `width: 100%` 与 `maxWidth: 100%`（填充父容器）；同步更新 `src/host/rawInventory.ts` 注释。
- **审计结论**：脚本注入的 Tailwind 基础层全部带 `#hhjgbim-vue-root` 前缀（dist 中 `.container` 工具类同理），不影响宿主；App.vue 侧边栏与 ProjectFilterPanel 均为 fixed/Teleport 定位，不占宿主布局流。
- 已通过 `tsc --noEmit`，dist 已重新构建。

## 更正：真正的根因是 Tailwind container 组件无前缀泄漏（上次修复无效）

- **推翻上一结论**：用户提供脚本应用前后网页快照（before.html/after.html，PROMaterialInventorynew 页）后，DOM 对比 + CSS 规则审计发现：`.abs100{position:absolute;width:100%}` 本身自适应，从未被锁死——上次改写它是无效修复，已 revert（`65d4d7b` → `336f830`）。
- **真实根因**：`tailwind.config.js` 的 `important: '#hhjgbim-vue-root'` 前缀机制**只作用于 utilities 层**；`.container` 属于 components 层，生成的 `.container{width:100%}` 及 `@media (width>=640px){.container{max-width:640px}}`…`@media (width>=1536px){.container{max-width:1536px}}` **无前缀泄漏全局**，命中宿主同名 `.container.abs100`，将其宽度锁到断点 max-width（≥1536px 窗口锁 1536px），缩放留白。
- **修复**：`tailwind.config.js` `corePlugins` 增加 `container: false`（项目未用 `.container` 类，禁用安全）。构建后验证 dist 已无 `.container` 规则、工具类前缀正常。
- **经验**：Tailwind `important: '<selector>'` 不覆盖 components 层（container 等），凡注入宿主页的 Tailwind 必须显式禁用 container 或确认 components 层无泄漏。
