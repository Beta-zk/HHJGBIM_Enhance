**⚠️ 重大环境事故与教训（务必遵守）**：
1. **本环境任何"删除文件"操作（`rm`、`git rm`、`fs.unlink/rmSync` 非 dist 目标）都会触发 safe-delete 机制误删整个目录树**——实测两次：`git rm` 4 个文件导致整个 `src/` 被 trash（丢全部文件含新建的 kernel/modules/host），恢复后又因 `git rm` 再次误删 `src/core/`；memory 日志追加内容也曾在事故中回滚丢失。
2. **铁律：永不物理删除文件**。需要"删除"时：用 Write 工具覆盖为弃用壳（`@deprecated` 注释 + `export {}`），git add 记录为 M。dist 除外（`node -e "fs.rmSync('dist',{recursive:true,force:true})"` 已验证安全）。
3. **关键防护：每完成一批文件改动立即 `git add` + `git commit`**，任何误删可 `git checkout HEAD -- <path>` 或 `git checkout-index -a -f` 恢复（索引里保留 staged 内容时用后者）。
4. git 索引历史路径为 `src/View/`（大写），checkout 恢复后磁盘与索引大小写已归一，勿再混用小写 `src/view/` 路径写文件（用 `src/View/`）。
