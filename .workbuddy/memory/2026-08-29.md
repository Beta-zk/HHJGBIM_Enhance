## performance-report 数据加工时机修复（commit 349fcc2）

- **症状**：爬虫离线时打开绩效面板无数据（用户误判为降级逻辑失效）。
- **根因**：组件经 uiStore 动态沙箱常驻挂载后，onMounted 仅执行一次且早于数据就绪（reportData 仍为空），processData 在空数据上运行；此后 show=true 只切换 v-if 显隐、不重新挂载，processData 永不重跑 → 面板空白。
- **教训**：**uiStore 常驻挂载的组件（root v-if 控制显隐）不能依赖 onMounted 处理数据**，须用 watch(store 显隐开关) 在打开后重跑数据加工；「先拉数据 → 后开窗」时序依赖此保障。
- 降级逻辑本身在 FactoryService.fetchMonthlyOutput（useLocal=false 走宿主接口）未受重构影响。
- 修复：watch(reportStore.show) → nextTick → processData()。验证：tsc + build 通过。

## project-state 路由切换重置 + 观察器提前注册（commit baf60d6）

**用户反馈**：① 小球挂载延迟 ~2s；② SPA 路由切换时筛选面板不响应（字块/勾选跨路由保持），仅 ctrl+r 刷新才遵循新逻辑。

**根因**：
- 延迟非 CPU 性能问题，是**字典预热网络链路**（ping + PLM_PROJECT_ENTITIES 串行请求）阻塞：matchMap 就绪前扫描无匹配 → 无小球。
- 路由不响应：store 全局单例，`populateFilterStates` 仅在"面板未显示或字块为空"时重建；路由切换后面板已显示 → 永不重建。且 `isExpanded`（悬浮窗展开态）是组件内部状态，切换后不归位。

**改动**：
- init 中注册 `ctx.dom.onRouteChange` → `isVisible=false` + `states=[]`，交由 DOM 扫描按新路由重建（重新应用名单排除策略）。
- **observer 提前注册**：init 即 `activateGlobalObserver()`（原为字典就绪后注册），字典就绪后仅 buildDictionary + debounceScan 补扫；顺带修复"字典预热失败 → 观察器永不注册"隐患。
- ProjectFilterPanel 新增 `watch(store.isVisible)` → 关闭时复位 `isExpanded`。
- 验证：tsc 通过；build 成功。

**待定优化**（用户未确认）：小球 2s 延迟的根治方案 = PLM 项目实体字典 localStorage 缓存（TTL），可将首屏挂载降至 ~100ms；需用户拍板存储策略。

## 内核面板多实例修复（commit 91e8650）

**症状**：宿主同源 iframe 嵌套新页面时，视口出现两个侧边内核面板。
**根因**：油猴脚本默认在 iframe 内也会注入（@match 匹配 iframe URL），`mountVueUI` 在 iframe 的 document 重复挂载；iframe 独立渲染上下文，父页面 z-index 无法穿透 → 视觉双面板。
**修复（三重防御）**：
- `vite.config.ts` userscript 加 `noframes: true`（产物 meta.js 已含 `@noframes`，脚本管理器不再向 iframe 注入）——最彻底。
- `main.ts` 顶部 `try { if (window.self !== window.top) return; } catch { return; }`——@noframes 未生效时的代码级兜底（含跨域 iframe 抛错场景）。
- `mountVueUI` 幂等：`#hhjgbim-vue-root` 已存在则跳过。
**说明**：面板 z-index 2147483646 已是 near-max（低于绩效视窗 2147483647，确保全屏视窗可覆盖），宿主正常元素无法盖住；"最顶层"由唯一性 + 高 z-index 共同保证。
**验证**：tsc 通过；build 成功；meta.js 确认含 `@noframes`。
